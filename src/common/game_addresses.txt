# Patterns Canopy finds its game addresses and fields with on a build that is
# not in game_builds.txt. Each line is one way to find one name:
#
#     <Name> code [at=<n>] <bytes>
#         The address is where the bytes match, plus n.
#     <Name> ref disp=<n> next=<n> to=code|data <bytes>
#         The bytes hold an instruction that reaches the address through a
#         rel32 or rip-relative displacement n bytes in, and the instruction
#         ends next bytes in. to says which kind of section the address must
#         land in.
#     <Name> rtti <decorated type name> [offset=<n>] [slot=<k>]
#         The vtable of that MSVC type, for its subobject at offset n. With
#         slot, the function in entry k of that vtable instead.
#     <Name> string <text> lea=<n> at=<n> <bytes>
#         The bytes hold a rip-relative lea, its displacement n bytes in,
#         that loads the one NUL-terminated string text. The address is that
#         match plus at. Tells apart template copies that differ only in the
#         name they register.
#     <Name> field read=<n> size=1|2|4 <bytes>
#         Not an address: a field of a game layout that game_retail.h
#         declares with GAME_FIELD. The value is the signed little-endian
#         integer of size bytes, read n bytes into the match, like the
#         displacement of an instruction that reads the field. A negative
#         value finds nothing.
#
# On a code or string line, at=start makes the address the entry of the
# function the match lies in, from the exception table, so code that moves
# inside its function is still found.
#
# Bytes are hex pairs or ?? for any byte, searched in the executable
# sections. A pattern counts only when it matches exactly once. A name with
# several lines is found when at least one line finds it and every line that
# finds something agrees.
#
# scripts/gen_address_patterns.py writes this file from the builds in
# game_builds.txt and keeps hand-written lines that still pass.
